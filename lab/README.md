# コンテナラボ

本書の参照コミット `9dd28f5e3526197b65a58306ce90248647c77777` を基にした、独立した `container` ブランチの拡張。セキュリティラボとは組み合わせていない。

## 起動

このリポジトリの直下で実行する。

```sh
make qemu
```

起動したシェルで実行する。

```sh
container run --image xv6-shell --cpu 1 --memory 8M --max-procs 8 /sh
```

`ls` でイメージの内容、`ps` で所属するプロセスを確認できる。空のプロンプトで Ctrl-D を入力すると終了する。シェルが終了するとカーネルが残ったメンバーも終了させ、外側の container コマンドが回収を待って専用ディレクトリを削除する。書き換えたファイルは保存しない。

## イメージ

コンテナイメージは、内部で使うプログラムやファイルをまとめたもの。このラボでは `tools/mkcontainer.py` がシェルと基本コマンドを `xv6-shell` に収録し、mkfs がそのファイルを起動ディスクへ入れる。カーネルは共有するため、イメージには含めない。起動時には `/c<起動コマンドのPID>-<連番>` を作り、各ファイルをコピーする。既存のディレクトリは再利用しない。

形式は8バイトの `XV6IMG1\0`、リトルエンディアンの32ビットファイル数、それに続く「16バイトのヌル埋めされた名前、32ビットの長さ、ファイル内容」。名前は14バイトまでで、通常ファイルだけをルートに配置する。ディレクトリやデバイス、スラッシュを含む名前、重複する名前、不完全なレコード、末尾の余分なデータを拒否する。ELFのデバッグ情報とシンボル表は生成時に除去する。Docker/OCIのイメージ形式には対応しない。

## カーネルの変更

- `containerenter(root, limits)` は呼び出し元を新しいコンテナへ所属させる。成功時は最初のプロセスのPIDをコンテナIDとして返す。既存の子プロセスがいる場合、既に所属している場合、不正な上限では失敗する。
- `getprocs(buf, capacity)` はプロセスの情報を返す。内部からは同じコンテナだけ、外部からは全体が見える。PIDはOS全体で共通。`ps` がこのAPIを使う。
- `namex()` はプロセスごとのルートを使い、その位置での `..` を同じディレクトリとして解釈する。開始時にはカレントディレクトリも変更する。
- 開いていたファイルは、0〜2番のコンソール以外を所属時に閉じる。コンテナ内ではデバイスの作成とopenを禁止する。コンソールは外部と共有する。
- `fork` は所属とルートを継承する。`kill` は内部から外部への要求を拒否する。外部からの管理操作は許可する。
- メモリはページ単位に丸めたユーザアドレス空間の予約量を合算する。遅延割り当て、ガードページ、exec中の新旧両方の領域も含む。物理ページだけの使用量ではない。カーネルのページテーブルやバッファは含めない。
- プロセス数とメモリは、ゾンビの状態でも保持し、waitで回収した時点で減らす。割り当て前に共有の使用量を予約し、失敗時に戻す。
- CPU時間はQEMU virtのtimeカウンタで計測し、各実行区間をコンテナ単位で合算する。1秒ごとの上限に達すると次の期間までスケジューラが選択しなくなる。`--cpu 1` は1秒あたりCPU 1個分で、専用CPUの確保ではない。既に実行中の処理は次のタイマー割り込みまで続くため、hartごとに最大約0.1秒の超過があり、厳密なリアルタイム制御ではない。

変更の中心は `kernel/proc.c`、`kernel/fs.c`、`kernel/sysfile.c`、`kernel/sysproc.c`、`kernel/exec.c`。共有ABIは `kernel/container.h`、イメージ展開と終了処理は `user/container.c` にある。シェルの引数配列を32要素に広げ、起動オプションを受け取れるようにしている。

コンテナ外のプログラムは管理側として信頼する。外部からルートのディレクトリを移動したり、外部ファイルのハードリンクを持ち込んだりする操作を防ぐアクセス権限は追加していない。ネットワーク分離、ディスク容量制限、入れ子、再起動後の残存ディレクトリの自動回収も対象外。

## 検証

```sh
make fmt
python3 tools/test_container.py --full
python3 tools/test_container.py --cpus 1 --skip-usertests
```

テストは一時ディスクを使うため、通常起動の `fs.img` を変更しない。実行記録は `lab/container-3cpu.log` と `lab/container-1cpu.log` に保存する。カーネル内の隔離・資源管理を `containertests` で検証し、イメージからの起動・再作成・異常時の回収と、既存の `usertests` を確認する。
